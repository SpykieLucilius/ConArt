## 2. What counts as a contribution

Contributions to this project include code, documentation, answering user questions, running the project's infrastructure, and advocating for all types of users.

---

## 3. Reporting a bug

To report a bug, open an issue using the [bug report template](bug-report.md) and provide all necessary information : 

* A clear and descriptive title.
* Steps to reproduce the issue.
* Expected and actual behavior.
* Any relevant logs, screenshots, or error messages.
* Environment details (e.g., operating system, software version).

If the bug is security-related, follow the instructions in the [security policy](security.md) instead of opening a public issue.

---

## 4. Proposing a change

Before opening an issue, make sure to search for existing issues to avoid duplicates.

To propose a change, open an issue using the [feature request template](feature-request.md) or the [RFC template](rfc.md), depending on the size and impact of the change.
Feature requests should be used for small proposals, while RFCs are for larger, more impactful changes.

Make sure to provide all necessary information for the request and the impact it will have.

---

## 5. Submitting a pull request

When submitting a pull request, make sure to follow the guidelines and provide all necessary information.
Branching strategy can be found [here](branching-strategy.md).

When providing evidence for your pull request, make sure to clearly state what evidence is being provided and how it supports your changes.

---

## 6. Scope of issues and pull requests

The scope of issues and pull requests is limited to discussions and work related to the project itself. Questions about usage, support requests, or disagreements with already made changes should be directed to the appropriate channels outside of the issue tracker and pull request system.

---

## 7. Licensing and sign-off

This project uses the Developer Certificate of Origin (DCO) for contributions. All contributors must sign off on their commits using the `Signed-off-by:` trailer.

---

## 8. AI-assisted contributions

When using AI-assisted tools for contributions, always state the following in your pull request description:

- The name of the tool used.
- The specific parts of the contribution that were assisted by the tool.
- Any human review or modifications made after using the tool.

You are responsible for disclosing the use of AI-assisted tools and ensuring that all contributions are properly reviewed and modified by a human before submission.
